# Step 2: Clip Review

This page is the media pool and the excerpt editor. It is reached from the [Memory page](./memory.mdx): **Advanced → Open the media pool** before a cut, or **Review the pool** after one. It has three screens in sequence: the media list (pick the pool), the analysis run, and **Review & Refine** (trim the clips the pipeline chose). The sidebar calls it **Clip Review**.

## Loading

When you arrive from the Memory page, a "Loading videos…" dialog fetches the videos, Live Photos and (if enabled) photos for your date range and person filter, plus thumbnails. Nothing is analyzed yet. Media that already has a cached analysis from the current model is tagged **Current analysis** on its card and is not re-sent to the LLM.

## The media list

The header shows the date range, clip count, total footage, HDR count and favorites count. Below it, "N Videos Found" (or "N Videos, M Photos Found") lists everything, grouped into one expansion per month ("March 2025 (12 clips)") with **Show more (N remaining)** pagination.

Each card shows the thumbnail, badges (Live, ★ favorite, HDR, 4K/HD), the cached analysis description and mood/setting tags when there is one, audio-category tags, date, duration, filename, resolution and colour space, and an **Include** checkbox. Photos get a camera badge.

Toolbar: a grid/list toggle. In grid view, click a thumbnail to toggle it; in list view use the checkbox.

All discovered videos and Live Photos start checked; photos start checked when photo support is on. Checked media is the pool the editor cuts from: untick what may never be used. Twins and bursts are the editor's to judge, so nothing here pre-deselects them.

## The "Generate Memories" panel

The expansion at the top holds the run settings:

- **Auto duration** switch. On (default) it shows "Auto · Xm YYs" — the type's target, or for Trip memories a media-aware estimate. Off shows a **Target duration (min)** field (0.25–60). It is the same duration as the Memory page's line.
- **HDR clips only**: drop SDR video from the pool.
- The **Generate Memories** button, which cuts from the checked pool.

## Running the analysis

Clicking **Generate Memories** replaces the list with a progress screen: the current editorial stage, the elapsed time and a **Cancel Pipeline** button. A first cut over a library that has not been read yet is the slow one; the readings are banked, so the next cut over the same period reuses them.

When it finishes you get "Pipeline complete! Planned N clips from M eligible media items." with counts for Media Eligible, Videos Deeply Analyzed, Clips Planned and Time Elapsed, then two buttons: **Review & Refine Selected Clips** or **Start Over (Select Different Clips)**.

## Review & Refine

Four metrics at the top: **Selected Clips**, **Total Duration**, **Target**, **Difference**. Bulk actions: **Set all to first 5s**, **Set all to middle 5s**, or a **Custom seconds** value with **Apply**.

Each planned clip is an expansion ("★ HDR March 03, 2025 • Using 5s of 12s") with:

- an **Include in compilation** checkbox
- a **Select range** slider for the excerpt, plus **Preview**, **First 5s**, **Last 5s**, **Middle 5s** and **Full clip** buttons (Preview swaps the thumbnail for an inline player)
- a **Rotation** select: Auto, 0°, 90° CW, 180°, 90° CCW

The **Final Duration** updates as you edit. Navigation: **Back to Selection**, **Re-run Analysis**, **Continue to Generation**.

## Photos in the list

When photo support is enabled (config or the **Include Photos** switch under Advanced on the Memory page), photos appear alongside video clips, merged into the same chronological list, with a camera badge and their own Include checkbox. Photos are auto-selected at generation time from the checked pool; see [Photo Support](../pipeline/photo-support.md).

## Cache

Analysis results live in a local SQLite database. Coming back to the same library later, cached clips are marked **Current analysis** and skip the expensive part; only new imports and clips analysed by an older model get re-analysed. Clear caches from the sidebar's **Cache** page.
