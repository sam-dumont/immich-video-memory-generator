# P0 Immich v2/v3 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep one client API while explicitly supporting Immich v2 and v3, with automatic major-version detection by default.

**Architecture:** Normalize server version and response-model differences at the API boundary. Cache one resolved major version per client and select version-specific upload fields before the multipart request is made. Generation, analysis, and UI code continue to consume one normalized `Asset` model.

**Tech Stack:** Python StrEnum, Pydantic v2 validators, httpx, pytest, respx-style mocked responses already used by the repository.

## Global Constraints

- `immich.api_version` accepts `auto`, `v2`, or `v3`; the default is `auto`.
- Documentation states v2/v3 support and the override values explicitly.
- `auto` reads `/api/server/version`, resolves by `major`, and caches the result per client.
- An explicit override does not call the version endpoint just to select an upload schema.
- Asset duration is exposed internally as seconds regardless of wire format.
- v3 upload multipart bodies never include `deviceAssetId` or `deviceId`.
- v2 upload behavior remains compatible with its required device identity fields.
- API errors preserve status, a useful message, structured details, and `X-Correlation-ID`.
- No feature code outside `api/` branches directly on Immich major version.
- Every task follows RED → GREEN → REFACTOR.

```python
class ApiVersionPolicy(StrEnum):
    AUTO = "auto"
    V2 = "v2"
    V3 = "v3"

class ResolvedApiVersion(StrEnum):
    V2 = "v2"
    V3 = "v3"

def resolve_api_version(policy: ApiVersionPolicy, server_major: int | None) -> ResolvedApiVersion:
    if policy is ApiVersionPolicy.V2:
        return ResolvedApiVersion.V2
    if policy is ApiVersionPolicy.V3:
        return ResolvedApiVersion.V3
    if server_major == 2:
        return ResolvedApiVersion.V2
    if server_major == 3:
        return ResolvedApiVersion.V3
    raise UnsupportedImmichVersion(f"Unsupported Immich major version {server_major}")
```

The exception message must include the supported values and the explicit override setting.

```python
@dataclass(frozen=True)
class ApiErrorDetails:
    message: str
    status_code: int
    correlation_id: str | None
    body: dict[str, Any] | list[Any] | str | None

def _message_from_body(body: Any) -> str | None:
    if isinstance(body, str):
        return body.strip() or None
    if isinstance(body, list):
        parts = [part for item in body if (part := _message_from_body(item))]
        return "; ".join(parts) or None
    if isinstance(body, dict):
        for key in ("message", "error"):
            if key in body and (message := _message_from_body(body[key])):
                return message
    return None

def parse_error_response(response: httpx.Response) -> ApiErrorDetails:
    try:
        body: dict[str, Any] | list[Any] | str | None = response.json()
    except (ValueError, TypeError):
        body = response.text.strip() or None
    message = _message_from_body(body) or f"HTTP {response.status_code}"
    return ApiErrorDetails(
        message=message,
        status_code=response.status_code,
        correlation_id=response.headers.get("X-Correlation-ID"),
        body=body,
    )
```

Prefer a non-empty string message; join a list of messages with `; `; otherwise use the
top-level `error`, then the response text, then `f"HTTP {response.status_code}"`. Copy only the parsed response
body into `details`. Catch `ImmichAPIError` in preflight and report status/correlation ID as
diagnostic metadata while preserving the existing user-facing check shape.
