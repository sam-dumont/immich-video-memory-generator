# Settings

**Settings** in the sidebar opens **Configuration** (`/settings/config`); **People** (`/settings/people`) and **Cache** (`/settings/cache`) appear under it once you are on a settings page. The CLI side of People is [`immich-memories people`](../cli/people.md), which writes the same file.

## People: confirming who's who

`/settings/people` is the editor for the people file (`~/.immich-memories/people.yaml`). The scan
reads every named person's picture count and month curve from Immich, and never a pixel. The page
shows what it inferred and gives you one place to answer.

**Start with a scan.** A fresh install shows "No people file yet" under the two buttons that fix
it. Press **Rescan the library**: it reads the counts, writes the file and draws the roster.
Rescan again whenever the library has changed. Everything under `inferred:` is recomputed by a
scan; everything you confirm on this page is written under `confirmed:` and a scan never touches
it. Confirmed beats inferred.

**The roster** lists people 20 to a page, inner circle first, busiest first within a tier. **Find
a name** above the pager narrows it to the names containing what you type. Each card carries the
tier the scan gave (`inner`, `recurring`, `episodic`, `event`) and the evidence behind it, the
birth date from Immich (read-only here: edit it in Immich), and a face crop. Face crops load as
the cards come into view, through the app's own media route, so a household of seventy is not
seventy requests before the page draws.

Three things on a card are yours to answer. **Role** is a list of suggestions you can ignore and
type over, saved the moment you pick it. **Notes** is free text for the editor's context, saved
once you stop typing for a second, and the same text typed twice is not written twice.
**Relationships** are the edges the scan proposed from co-appearance, birth dates and month
curves, each with its confidence: ✓ confirms, ✗ rejects, and pressing the same answer again takes
it back. **Add relationship** records one the scan missed; one answer updates both people.
Confirmed edges show a badge and a delete icon; inferred ones stay proposals until you answer.

**Add someone not in Immich** creates a person with no face record, for somebody who matters to
the stories but was never tagged. They get a local id and can carry relationships like anyone else.

**Curation** at the top lists what only Immich can fix: two records with one name, or a person
split across records. Each flag links to the record in Immich.

Nothing on this page reloads the browser: a role change, a note, an added person or a removed
relationship redraws the roster in place and keeps your place on the page.

## Config: what is actually running

`/settings/config` is a **read-only viewer**. It shows the merged, live configuration: what `~/.immich-memories/config.yaml` holds, after environment overrides and after any active preset has filled in the knobs you did not set. It is the answer to "the docs say the default is X, but is X what this install is using?"

Each config section is a collapsible panel with its key count. `immich`, `analysis`, `output` and `defaults` are open on arrival; the rest start collapsed. If a preset is active, the page names it and says it is filling the values you have not set.

**Reload from Disk** re-reads `config.yaml` and refreshes the page. Use it after editing the file by hand: the running process holds the config in memory and will not otherwise notice. The config file path is printed beside the button, so you know which file you are editing. Every key and its default is in the [configuration reference](../../reference/config-reference.md).

:::note There is no Save button on this page
Saving is on the **Memory** page, under Advanced, not here. This page only reads.
:::

### Secrets are masked

Any key named `api_key`, `api_keys`, `caption_api_key`, `client_secret`, `password`, `secret`, `token`, `trigger_token` or `urls` renders as `***`: a full mask, not a partial one. An earlier version showed the first and last few characters of every secret, `auth.password` included, which is a preview of a password rather than a redaction.

The masking is server-side, so a screenshot of this page for a bug report has nothing left to leak.

## Saving config from the Memory page

The connection panel under **Advanced** on the [Memory page](./memory.mdx) has a **Save Config** button. It writes the Immich URL and API key you entered, but it saves the **whole configuration**, not just those two fields.

That has a consequence worth understanding before you press it: **every value becomes explicitly set.** A preset works by filling in what you have not chosen, so once everything is written to the file, there is nothing left for the preset to own. `preset: fast` will still be named, but the values it would have supplied are now yours and will not move again. To put the preset back in charge of something, delete those keys from `config.yaml` by hand.

Two exceptions to "everything is written":

- **`server.host`** is omitted unless you set it deliberately. Writing the wildcard default would make the next load read it as a deliberate LAN bind and silently retire the localhost default.
- **Credentials supplied through environment variables** stay in the environment; they are not baked into the file.

## Cache: what is on disk, and getting rid of it

`/settings/cache` lists four caches with their current size, each with its own **Clear** button, plus a clear-everything action.

| Cache | Holds | Cost of clearing |
|-------|-------|------------------|
| **Analysis** | a SQLite table the retired clip scorer used to fill | nothing: no code writes it any more |
| **Video** | downloaded source videos | re-download from Immich; bounded by the cache size limit and evicted automatically |
| **Thumbnail** | Immich previews, read back for pixel facts, the context heads, contact sheets, captions and the clip review grid | re-fetched from Immich on demand, and re-captioned where a banked caption failure no longer matches |
| **Preview** | the `.mp4` previews the review page plays back | regenerated when you next preview |

Nothing on that list is lost for good: every one of the four rebuilds itself from Immich plus
compute. Clear the **video** or **thumbnail** caches when you want the disk back.

The expensive thing on disk is not in that list and not behind those buttons: the editor's banks
live in `annotations.sqlite` under the cache directory, and hold every caption, head answer,
detector verdict and reading. **Clear all caches** does not touch it, which is the right default.
Delete it and the next cut re-reads your library from scratch.
