# Settings

Three pages sit outside the memory flow, reachable from the sidebar at any time: **Config** (`/settings/config`), **People** (`/settings/people`) and **Cache** (`/settings/cache`). The CLI side of People is [`immich-memories people`](../cli/people.md), which writes the same file.

## People: confirming who's who

`/settings/people` is the editor for the people file (`~/.immich-memories/people.yaml`). The scan
reads every named person's picture count and month curve from Immich, and never a pixel. The page
shows what it inferred and gives you one place to answer.

**Start with a scan.** A fresh install shows "No people file yet" under the two buttons that fix it. Press **Rescan the library**:
it reads the counts, writes the file and draws the roster. Rescan again whenever the library has
changed. A scan recomputes `inferred:` and preserves `confirmed:` from a valid existing file.
Back up the file before editing it by hand: malformed or unreadable YAML is treated as empty,
and a later scan or save can replace it. If the log says "starting fresh", fix or restore it first.

**The roster** lists people 20 to a page, inner circle first, busiest first within a tier. **Find a name** above the pager narrows it to the names containing what you type. Each
card carries the tier the scan gave (`inner`, `recurring`, `episodic`, `event`) and the evidence
behind it, the birth date from Immich (read-only here: edit it in Immich), and a face crop.
Face crops load as the cards come into view, through the app's own media route, so a household
of seventy is not seventy requests before the page draws.

**What you can answer on a card:**

- **Role**: the list is suggestions; pick one or type your own. Saved when you pick it.
- **Notes**: free text for the editor's context, saved once you stop typing for a second. The
  same text typed twice is not written twice.
- **Relationships**: the scan proposes edges (co-appearance, birth date, month curves) with its
  confidence. ✓ confirms, ✗ rejects, pressing the same answer again takes it back. **Add
  relationship** records one the scan missed; one answer updates both people. Confirmed edges
  show a badge and a delete icon; inferred ones stay proposals until you answer.

**Add someone not in Immich** creates a person with no face record, for somebody who matters to
the stories but was never tagged. They get a local id and can carry relationships like anyone else.

Nothing on this page reloads the browser: a role change, a note, an added person or a removed
relationship redraws the roster in place and keeps your place on the page.

**Curation** at the top lists what only Immich can fix: two records with one name, or a person
split across records. Each flag links to the record in Immich.

## Config: viewing the saved settings

`/settings/config` is a **read-only viewer** of the default config file, with environment
overrides and preset defaults applied. It reloads `~/.immich-memories/config.yaml` when opened.

It is not a complete view of an existing Memory session: that session retains settings loaded
earlier. The viewer also does not follow a custom `--config` path used to launch the UI. For
consistent results after changing config, restart the UI and start a new session.

Each config section is a collapsible panel with its key count. `immich`, `analysis`, `output` and `defaults` are open on arrival; the rest start collapsed.

If a preset is active, the page names it and says it is filling the values you have not set.

### Secrets are masked

Known secret fields are masked server-side, including API keys, `caption_api_key`, passwords,
trigger tokens and notification URLs. Names, hostnames and other configuration values remain
visible; review the page before sharing a screenshot.

### The two actions

- **Reload from Disk** re-reads the default config file and refreshes this viewer. It does not
  reset settings already held by a Memory session.
- The **config file path** is printed beside the button, so you know which file you are editing.

:::note There is no Save button on this page
Saving is on the **Memory** page, under Advanced, not here. This page only reads.
:::

## Saving config from the Memory page, and what it costs you

The connection panel under **Advanced** on the [Memory page](./memory.mdx) has a **Save Config** button. It writes the Immich URL and API key you entered, but it saves the **whole configuration**, not just those two fields.

That has a consequence worth understanding before you press it: **every value becomes explicitly set.** A preset works by filling in what you have not chosen, so once everything is written to the file, there is nothing left for the preset to own. `preset: fast` will still be named, but the values it would have supplied are now yours and will not move again.

If you want the preset back in charge of something, delete those keys from `config.yaml` by hand.

Two exceptions to "everything is written":

- **`server.host`** is omitted unless you set it deliberately. Writing the wildcard default would make the next load read it as a deliberate LAN bind and silently retire the localhost default.
- **Credentials supplied through environment variables** stay in the environment; they are not baked into the file.

## Cache: what is on disk, and getting rid of it

`/settings/cache` lists three media caches with their current size and a **Clear** button.
**Clear media caches** clears all three.

| Cache | Holds | Cost of clearing |
|-------|-------|------------------|
| **Video** | downloaded source videos | re-download from Immich; bounded by the cache size limit and evicted automatically |
| **Thumbnail** | Immich previews, read back for pixel facts, the context heads, contact sheets, captions and the clip review grid | re-fetched from Immich on demand, and re-captioned where a banked caption failure no longer matches |
| **Preview** | the `.mp4` previews the review page plays back | regenerated when you next preview |

The expensive thing on disk is not in that list and not behind those buttons: the editor's banks
live in `annotations.sqlite` under the cache directory, and hold every caption, head answer,
detector verdict and reading. **Clear media caches** leaves it and the run history intact.
If you delete it, the next cut must rebuild annotations for its scope.

Of what the page does clear: nothing generated is lost, every one is rebuildable from Immich plus
compute. Clear the **video** or **thumbnail** caches when you want the disk back.
