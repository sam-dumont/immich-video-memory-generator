# Your First Memory

This walks you through one video from start to finish. Set up the annotation producers before
the first run: a cold cut reads and describes every picture in the period, which is the slow part,
and everything it reads is kept.

## Prerequisites

Before you start:

- **Immich v2 or newer** with an API key (Account Settings > API Keys > New API Key — grant **All**, or at least read access to assets/people/albums/timeline/search plus asset upload + album create/update if you want upload-back)
- **Docker** or **Python 3.11+** installed
- **~2 GB free disk** for the video cache (downloaded clips get cached locally)
- Photos, Live Photos or videos in the period you want
- [Editorial annotation setup](../deploy/configuration/editorial-preparation.md): the pinned
  encoder and detector weights, the compact-caption endpoint, and a configured text model

## Step 1: Launch

**Docker** (recommended):

```bash
# Create a .env file
cat > .env << 'EOF'
IMMICH_URL=https://photos.example.com
IMMICH_API_KEY=your-api-key-here
EOF

# Download and start
curl -O https://raw.githubusercontent.com/sam-dumont/immich-video-memory-generator/main/docker-compose.yml
docker compose up -d
```

**Or native install:**

```bash
uvx --from "immich-memories[editorial]" immich-memories ui
```

Open [http://localhost:8080](http://localhost:8080) in your browser. Both routes keep the UI on
localhost: the native install binds loopback, and the compose file publishes the port there. If
the app runs on a different machine than your browser, see the
[Docker install page](../deploy/installation/docker.md#quick-start) — it pairs publishing the
port with turning on authentication.

## Step 2: Connect to Immich

With credentials in the config or the environment the page connects on its own and shows the
brief. Otherwise it shows only the **Immich Connection** panel: enter the server URL and API key
and click **Test Connection**. On success the panel collapses to "Immich Connection — *you*" and
the brief appears.

<ThemedScreenshot name="memory-brief" alt="The brief, connected to Immich" />

## Step 3: Pick a month

Choose **Monthly Highlights** as the memory type and pick a month with a fair number of pictures
in it. A month is the right first cut: one minute of output, and the reading is over in minutes
rather than the hour a whole year can take on a cold library. Leave **Auto duration** on.

## Step 4: Cut

Press **Cut**. The page loads the pool for the brief and shows one row per phase — finding media,
loading thumbnails, reading the pictures, editing, done — with the editor's own stage beside the
active row. The first cut prepares a caption and facts for every picture in the month, then reads
the month's episodes and account, weighs its stories, and picks the moments. A missing producer
stops the run here and says which one.

Reloading the page mid-cut is fine: it lands on the same rows.

<ThemedScreenshot name="memory-cutting" alt="The cut in progress" />

## Step 5: Read the story

When it finishes the page shows what the editor made of the month: a one-paragraph thesis, a
duration line, and the stories heaviest first — each with its purpose and, under it, every
picture it was granted with a **Still** or **Motion** badge, the seconds it holds, and the reason
it is there.

<ThemedScreenshot name="memory-story" alt="The story the cut produced" />

If a picture should not be in it, **Review the pool** opens the media pool with the cut's picks,
where you untick it and trim excerpts. **Cut again** runs the editor once more over the same
pool; **Change the brief** starts over.

## Step 6: Export

Press **Export**. The Preview & Export page shows the summary and the output filename; the
defaults work for a first video. Music, title and resolution live one click away under **Back to
Generation Options** — the only one worth changing on a first run is **Background music**, if you
have a specific track you want.

Click **Generate Video**. The status line walks through the run: downloading clips and extracting
segments, assembling with transitions and title screens, "Applying music" (or "Music disabled"),
"Uploading to Immich" (or "Delivery not requested"), then "Complete".

<ThemedScreenshot name="memory-export" alt="Export: output filename and Generate Video" />

Most of the wait on a first run is the cut, not the encode; on the second cut over the same
month the reading is already banked. Of the render that is left, the title screens cost more
than the encoder: at 2 cores, titles were ~263 s of a ~339 s assembly
([CPU-Only Mode](../deploy/hardware/cpu-only.md#title-rendering-is-the-bottleneck-not-encoding)).

## Step 7: Watch

When it's done, the built-in player shows your result and "Saved to:" gives the file path (a
per-run folder under `~/Videos/Memories` by default). If you turned on **Upload after
generation**, it is also in the Immich album you named.

## What just happened?

The app fetched the month's source metadata and previews, prepared a description and facts for
every eligible picture, and read the stories those pictures show. It weighed the stories against
the month's account, gave each the pictures its weight earned, and assembled them in
chronological order with FFmpeg, titles and music. Every attempt is kept under the cache
directory, with the plan and the reason for every picture.

Facts and readings are cached by their producer and exact input. A later cut reuses matching
results; changed or missing evidence requires fresh work.
